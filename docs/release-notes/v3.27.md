Two bugs found by hand, fixed and verified against the full 41-suite emulator run.

## Fixed

- **Victory music kept playing after a wild encounter.** Beating or catching a wild Pokémon plays victory music, but dismissing that result and returning to the main screen never stopped it — the trainer/gym win screen has its own dismiss path that correctly silences the music, but a wild encounter's simpler message-dismiss never went through it. The music now stops on the same tap that closes the battle screen, whether you caught something, just won, or picked up an item drop along the way.
- **LAN battle names could, in principle, get crossed under packet loss.** Tracing the pairing handshake turned up a real bug: your own name and your opponent's name shared a single field internally, and a resend during a slow or lossy pairing could echo your opponent's name back to them instead of sending your own. In practice this never showed up — a normal pairing finishes before the resend timer that triggers it ever fires, which is why testing it repeatedly never caught anything — but it's fixed properly now: your own name and the name you display for your opponent are two separate fields that can no longer cross-contaminate.

## Also

- A regression test (`focus_test.cpp`) was asserting the *old* behavior for a total save-write failure during a party swap — that the incoming Pokémon stayed live in memory for a later save to "catch up" on. The actual code rolls back to whichever Pokémon was out before instead, which turns out to be the more correct design: leaving the incoming one live without committing the party slot would just be the same duplicate-Pokémon bug pointed the other direction. The test (and the doc note describing it) now match what the code actually does.

Existing saves are unaffected by any of this.
